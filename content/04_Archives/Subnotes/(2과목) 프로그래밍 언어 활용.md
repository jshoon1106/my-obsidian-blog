## 1. 프로그래밍 언어 활용

### 1.1 기본문법 활용
#### 1.1.1 데이터 타입
- **정의**: 변수에 저장될 데이터의 종류 및 메모리 크기를 정의하는 분류 체계
- **의의**: 데이터 표현 범위 설정 및 메모리 할당의 효율성 보장
- **원리 및 예시**:
	- 정수형: `char` (1byte), `short` (2byte), `int` (4byte), `long` (4/8byte)
	- 실수형: `float` (4byte), `double` (8byte)
	- 논리형: `bool`/`boolean` (1byte)

#### 1.1.2 변수
- **정의**: 데이터 값을 기억하기 위해 이름이 부여된 메모리 공간
- **의의**: 동적인 데이터 저장, 참조 및 연산 처리의 기본 수단
- **원리 및 예시**: 변수 선언 및 초기화, 전역변수 vs 지역변수, 스코프(Scope) 및 생명주기

#### 1.1.3 연산자 및 명령문
- **정의**: 데이터 연산을 수행하는 연산자 기호 및 프로그램 실행 흐름을 제어하는 명령문
- **의의**: 연산자 우선순위 및 제어문(조건문·반복문)을 통한 로직 구현
- **원리 및 예시**:
	- 연산자: 산술, 관계(`==`, `!=`), 논리(`&&`, `||`), 대입, 증감(`++`, `--`), 삼항 연산자
	- 제어문: 조건문(`if...else`, `switch...case`), 반복문(`for`, `while`, `do...while`), 제어 이동(`break`, `continue`)

---

### 1.2 언어특성 활용
#### 1.2.1 절차적 프로그래밍 언어
- **정의**: 순차적인 명령 실행과 함수(프로시저) 호출을 중심 구조로 갖는 언어
- **의의**: 컴퓨터 동작 구조와 직결된 직관적인 순차 로직 구현
- **원리 및 예시**: C 언어 - 포인터 연산자(`*`, `&`), 구조체(`struct`), 함수 정의 및 매개변수 전달(Call by Value / Call by Reference)

#### 1.2.2 객체지향 프로그래밍 언어
- **정의**: 객체 간의 메시지 교환 및 관계 설정을 중심으로 시스템을 구현하는 언어
- **의의**: 대규모 개발 시 코드 재사용성 및 확장성 극대화
- **원리 및 예시**: Java/C++ - 클래스, 인스턴스, 접근 제어자(`public`, `private`), 생성자, 오버로딩 vs 오버라이딩

#### 1.2.3 스크립트 언어
- **정의**: 별도의 컴파일 과정 없이 인터프리터가 즉시 해석하여 실행하는 언어
- **의의**: 신속한 개발 및 파일·데이터 조작 자동화 용이
- **원리 및 예시**: Python/JavaScript - 동적 데이터 타입, 리스트 컴프리헨션, 딕셔너리, 슬라이싱 연산

---

### 1.3 라이브러리 활용
#### 1.3.1 데이터 입출력
- **정의**: 표준 입력 장치(키보드) 및 출력 장치(모니터)와 데이터 전송을 주고받는 기능
- **의의**: 사용자 및 외부 시스템과의 기본 데이터 상호작용
- **원리 및 예시**: C(`printf`, `scanf`), Java(`System.out.println`, `Scanner`), Python(`print`, `input`)

#### 1.3.2 파일 입출력
- **정의**: 하드디스크 등 보조기억장치에 텍스트나 바이너리 파일 형태로 데이터를 읽고 쓰는 기능
- **의의**: 데이터 영속성(Persistence) 유지 및 로깅/환경설정 파일 관리
- **원리 및 예시**: C(`fopen`, `fclose`, `fprintf`), Java(`FileReader`, `BufferedReader`), Python(`open()`, `with` 문)

#### 1.3.3 예외 처리
- **정의**: 프로그램 실행 중 발생하는 런타임 오류를 비정상 종료 없이 안전하게 제어하는 기법
- **의의**: 프로그램의 복구 능력 및 실행 연속성 확보
- **원리 및 예시**: `try ... catch ... finally` (Java), `try ... except ... else ... finally` (Python), 예외 던지기(`throw`/`raise`)

#### 1.3.4 프로토타입
- **정의**: 언어 차원에서 객체의 원형(Prototype)을 이용해 상속 구조 및 속성을 공유하는 구조
- **의의**: 자바스크립트 등 프로토타입 기반 언어의 객체 상속 원리 이해
- **원리 및 예시**: JavaScript `prototype` 체인 및 객체 생성자 함수

## 2. 프로그램 구현

### 2.1 개발환경 구축
#### 2.1.1 개발환경 구축
- **정의**: 서버 프로그래밍 및 응용 프로그램 구현에 필요한 런타임 및 개발 라이브러리 환경 설정
- **의의**: 안정적인 애플리케이션 빌드 및 실행 보장
- **원리 및 예시**: JDK 버전 설정, 웹 애플리케이션 서버(WAS) 연동

#### 2.1.2 서버 프레임워크 이해
- **정의**: 서버 개발을 위한 기본 구조, 라이브러리, 모듈 세트를 제공하는 개발 뼈대
- **의의**: 표준화된 개발 구조 강제 및 구축 시간 단축
- **원리 및 예시**: Spring Framework (Java), Django/Flask (Python), Node.js/Express (JS)

---

### 2.2 공통 모듈 구현
#### 2.2.1 재사용
- **정의**: 이미 검증된 소프트웨어 모듈 및 함수를 새로운 개발 시 수정 없이 다시 활용하는 기법
- **의의**: 생산성 향상, 테스트 비용 감소, 품질 안정화
- **원리 및 예시**: 함수 재사용, 라이브러리 재사용, 컴포넌트 재사용

#### 2.2.2 모듈화 기법
- **정의**: 복잡한 시스템을 독립된 기능을 수행하는 작고 관리하기 쉬운 모듈 단위로 분할하는 기법
- **의의**: 수정이 용이하고 시스템 유지보수가 간편해짐
- **원리 및 예시**: 모듈 분할 원칙 (고응집도, 저결합도)

#### 2.2.3 결합도
- **정의**: 모듈과 모듈 간의 상호 의존성 및 연결 정도를 나타내는 척도 (낮을수록 우수)
- **의의**: 의존성을 줄여 독립적인 변경이 가능하게 함
- **원리 및 예시**:
	- 결합도 순서 (약함/우수 → 강함/나쁨):
	- 내용(Content) > 공통(Common) > 외부(External) > 제어(Control) > 스탬프(Stamp) > 자료(Data)

#### 2.2.4 응집도
- **정의**: 모듈 내부의 구성요소들이 단일 목적을 위해 얼마나 밀집되어 있는지 나타내는 척도 (높을수록 우수)
- **의의**: 모듈 본연의 기능 독립성 및 단일 책임 보장
- **원리 및 예시**:
	- 응집도 순서 (강함/우수 → 약함/나쁨):
	- 우연적(Coincidental) < 논리적(Logical) < 시간적(Temporal) < 절차적(Procedural) < 통신적(Communication) < 순차적(Sequential) < 기능적(Functional)

---

### 2.3 화면 구현
#### 2.3.1 UI 프레임워크
- **정의**: 사용자 화면 레이아웃 및 반응형 컴포넌트를 용이하게 구축할 수 있도록 지원하는 프레임워크
- **의의**: 표준화된 일관된 디자인 시스템 적용
- **원리 및 예시**: React, Vue.js, Bootstrap

#### 2.3.2 HTML, CSS, JAVASCRIPT
- **정의**: 웹 클라이언트 화면 구현을 구성하는 3대 핵심 기술 언어
- **의의**: 브라우저 기반 사용자가 직접 조작하는 UI/UX 구현
- **원리 및 예시**:
	- HTML: 웹 문서 구조 및 태그 정의 (`<div>`, `<form>`, `<input>`)
	- CSS: 디자인 스타일 및 레이아웃 정의 (Flexbox, Grid, CSS 선택자)
	- JAVASCRIPT: 동적 이벤트 제어 및 DOM 조작 (`addEventListener`, `fetch`)

---

### 2.4 서버 프로그램 구현
#### 2.4.1 보안 취약성 개념
- **정의**: 서버 프로그램 구현 시 발생할 수 있는 소스 코드 차원의 취약점 및 위협 요소
- **의의**: 시큐어 코딩(Secure Coding) 가이드를 준수하여 보안 사고 사전 예방
- **원리 및 예시**: SQL Injection(입력값 검증 미흡), XSS(크로스 사이트 스크립팅), 널 포인터 역참조

#### 2.4.2 API
- **정의**: 애플리케이션 간에 데이터를 주고받기 위한 상호작용 인터페이스 표준 규격
- **의의**: 시스템 간 데이터 연동 및 서비스 통합 구현
- **원리 및 예시**: RESTful API (HTTP Method: GET, POST, PUT, DELETE / JSON 데이터 포맷)

#### 2.4.3 인터페이스 이해
- **정의**: 내·외부 시스템 간 데이터 교환 및 통신을 위해 정의한 연계 명세 구조
- **의의**: 이종 시스템 간 신뢰성 있는 전송 및 변환 처리
- **원리 및 예시**: JSON, XML, 연계 메커니즘 (DB 링크, API, 소켓)
