```javascript
## hbase-kafka.py
## hbase.py: hbase 구조로 저장
## consumer.py: ratings 토픽에 불러온 파일을 읽고 메세지 전송
from kafka import KafkaConsumer
import happybase
import json

consumer = KafkaConsumer(bootstrap_servers="localhost:9092"
    , auto_offset_reset="earliest"
    , value_deserializer=lambda v: json.loads(v.decode("utf-8"))
    , consumer_timeout_ms=3000)
consumer.subscribe(['ratings'])

## ratings 토픽의 메세지를 Hbase 형식으로 저장

connection = happybase.Connection('192.168.56.100', 9090)

if b'ratings' not in connection.tables():
    connection.create_table('ratings', {'cf': dict()})
table = connection.table('ratings')
batch = table.batch(batch_size=1000)
count = 0

for message in consumer:
    batch.put(message.value['userId']+'_'+message.value['movieId'], {
        b'cf:rating': message.value['rating'],
        b'cf:timestamp': message.value['timestamp']
    })
    count += 1
    if count%1000==0:
        print(f"now={count}")
batch.send()
```

> [!note]+ 🌊 빅데이터 파이프라인 전체 구조 설명
> ### 1. 데이터 소스 (Data Sources / Producers)
> 
> - **기능:** 웹사이트, 모바일 앱, 센서, 기존 관계형 데이터베이스(RDBMS) 등 실시간으로 데이터를 만들어내는 **출발점**입니다.
> - **역할:** 사용자 로그, 클릭 이벤트, 트랜잭션 데이터 등을 쉼 없이 발생시켜 파이프라인(Kafka)으로 밀어 넣습니다.
> 
> ### 2. Apache Kafka (카프카) - *메시지 브로커 / 데이터 수집*
> 
> - **기능:** 쏟아지는 대용량 데이터를 안전하게 받아두는 '초고속 물류 센터(버퍼)'입니다.
> - **역할:** 1번(데이터 소스)에서 오는 데이터를 빠르게 받아 토픽(Topic)별로 차곡차곡 쌓아둡니다. 데이터가 유실되지 않도록 보관하며, 뒤에 있는 처리 엔진(Spark)이 자기 속도에 맞춰 데이터를 가져갈 수 있도록 완충 역할을 합니다.
> 
> ### 3. Zookeeper (주키퍼) - *분산 코디네이터*
> 
> - **기능:** 분산 시스템이 잘 돌아가도록 돕는 '교통 경찰'이자 '오케스트라 지휘자'입니다.
> - **역할:** 2번의 Kafka 클러스터(여러 대의 서버) 상태를 모니터링하고 관리합니다. 어떤 서버가 살아있는지, 리더는 누구인지 등 중요한 메타데이터를 관리하여 시스템이 안정적으로 유지되도록 돕습니다.
> 
> ### 4. Spark & Spark Streaming (스파크) - *분산 데이터 처리 엔진*
> 
> - **기능:** 메모리 기반으로 데이터를 엄청나게 빠르게 분석하고 가공하는 '초고속 데이터 공장'입니다.
> - **역할:** Kafka에 쌓인 데이터를 실시간(또는 아주 짧은 주기의 마이크로 배치)으로 빨아들여 필터링, 형식 변환, 집계 등의 연산을 수행합니다. 기존의 하둡(MapReduce)보다 처리 속도가 월등히 빠릅니다.
> 
> ### 5. Spark MLlib (스파크 머신러닝) - *기계 학습 라이브러리*
> 
> - **기능:** Spark 내에 내장된 'AI 브레인(연구소)'입니다.
> - **역할:** Spark가 처리 중인 데이터를 바탕으로 머신러닝 모델(예: ALS 기반 상품/영화 추천 알고리즘, 군집화, 분류 등)을 학습시키고, 실시간으로 예측(Prediction) 결과를 만들어냅니다.
> 
> ### 6. NoSQL HBase (에이치베이스) - *실시간 분산 데이터베이스*
> 
> - **기능:** 가공 및 분석이 완료된 데이터를 빠르게 넣고 뺄 수 있는 '초고속 서랍장'입니다.
> - **역할:** Spark(4, 5번)가 열심히 분석하고 만들어낸 결과물(예: 유저별 추천 리스트)을 저장합니다. NoSQL 특성상 방대한 데이터 속에서도 특정 데이터를 실시간으로 조회(Random Read/Write)하는 데 매우 최적화되어 있습니다.
> 
> ### 7. Hadoop (하둡 / HDFS) - *분산 파일 시스템 (저장 및 관리 기술)*
> 
> - **기능:** 페타바이트급 데이터를 안전하게 보관하는 '거대한 무한 지하 창고'입니다.
> - **역할:** 6번의 HBase가 겉으로 보이는 서랍장이라면, 하둡(HDFS)은 그 서랍장이 물리적으로 위치한 거대한 저장 공간입니다. 값싼 서버 여러 대를 묶어 하나의 큰 디스크처럼 사용하며, 데이터의 복제본을 유지해 안전성을 보장합니다.
> 
> ### 8. 데이터 소비 (Consumers / Client Apps)
> 
> - **기능:** 최종적으로 가치를 창출하는 **사용자 접점**입니다.
> - **역할:** 웹 애플리케이션, 모바일 앱, 또는 BI(비즈니스 인텔리전스) 시각화 대시보드 등이 여기에 해당합니다. HBase에 저장된 분석 결과(예: 추천 상품)를 실시간으로 조회하여 사용자 화면에 띄워줍니다.
>

- 주요 기능
    - 데이터 스트림의 모델화(추상화)
        - **무한 테이블(Unbounded Table)**: 실시간 데이터 스트림을 끝이 없이 계속해서 행(row)이 추가되는 하나의 큰 테이블로 간주합니다.
        - **데이터 추가 매커니즘**: 새로운 데이터가 입력 스트림에 들어오면, 이 데이터들은 '무한 테이블'의 새로운 행으로 추가(Append)됩니다.
        - **DStream 구조**: 내부적으로는 시간대별로 데이터가 구분됩니다. 예를 들어 time 0~~1 사이의 데이터는 'RDD @ time 1'로, time 1~~2 사이의 데이터는 'RDD @ time 2'와 같은 개별 RDD(Resilient Distributed Dataset) 단위로 나뉘어 처리됩니다.
    - 예시 — '단어 개수 세기(Word Count)'
        - **입력(Input)**: 특정 시간(t=1, t=2, t=3)마다 새로운 단어 데이터(cat, dog, owl 등)가 입력 스트림을 통해 들어옵니다.
        - **무한 테이블 업데이트**: 시간이 지남에 따라 모든 입력 데이터가 누적되어 저장되는 전체 입력 테이블의 모습을 보여줍니다.
        - **결과 테이블(Result Table)**: 입력 데이터에 대해 쿼리(예: 단어 개수 세기)를 수행한 결과가 담기는 테이블입니다.
            - t=1일 때: cat 1, dog 3
            - t=2일 때: 신규 데이터(dog, dog)가 추가되어 cat 2, dog 3, owl 1로 업데이트
            - t=3일 때: 추가 데이터가 반영되어 cat 2, dog 4, owl 2로 최종 업데이트
        - **출력 모드(Complete Mode)**: 업데이트가 발생할 때마다 계산된 전체 결과(counts)를 콘솔 등에 모두 출력하는 방식을 설명합니다.
