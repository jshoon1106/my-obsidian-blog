                                - ==기본키==(Primary key)(후보키에서 선택된 키)
                                - 대체키(Alternate key)(선택되지 못한 후보키)

                                - 기본키의 속성 만족해야 함
                                - 내 릴레이션의 기본키를 참조할 수도 있다

                - 참조(Referential) 무결성 제약 조건
                    - 외래키는 참조할 수 없는 값을 가질 수 없음

    - <u>SELECT</u>, <u>HAVING</u> 절에서 사용 가능
    - 계산값에 대해 [AS 속성명]으로 별도의 속성명 지정
    - WHERE(조건) 연산 이후 계산됨
    - NULL —> COUNT에서 제외

    - 같은 속성값을 가진 튜플을 (HAVING 조건(그룹별로 조건 연산) 이후) 그룹

```sql
SELECT COUNT(*) AS 고객수, AVG(적립금) AS 적립금_평균 FROM 고객 GROUP BY 등급 HAVING AVG(적립금)>=1000
SELECT 주문제품, 주문고객, SUM(수량) AS 총주문수량 FROM 주문 GROUP BY 주문제품, 주문고객
```

            1. **타임스탬프 순서 (Timestamp Ordering) 기법**
> 
> - **타임스탬프 (**$TS$**):** 트랜잭션이 시스템에 진입할 때 부여받는 유일한 식별자입니다.
>     - **시스템 시계(System Clock)** 값을 그대로 부여하거나, 트랜잭션 발생 시마다 카운터를 하나씩 증가시키는 논리적 계수기(Logical Counter)를 사용합니다.**직렬성 보장:** 만약 트랜잭션 $T_i$가 $T_k$보다 먼저 실행되었다면 ($TS(T_i) < TS(T_k)$), 시스템은 <$$T_i, T_k$>의 직렬 실행 결과와 일치하도록 보장합니다.
> - 트랜잭션이 시작할 때 유일한 시스템 시간(또는 논리적 카운터)인 **타임스탬프**를 부여합니다.
> - 트랜잭션 간의 실행 순서를 이 타임스탬프 순서대로 직렬화하도록 보장합니다.

                - 장점 및 단점
                    - **장점**: 대기가 없으므로 **교착상태(Deadlock)가 발생하지 않습니다.**
                    - **단점**: 연쇄 복귀나 기아(Starvation) 현상이 발생할 수 있습니다.
                - **Thomas의 기록 규칙 (Thomas' Write Rule)**
                    - 타임스탬프 순서 기법의 변형으로, 자신보다 최신 트랜잭션이 이미 데이터를 갱신했다면 현재 트랜잭션의 쓰기(Write) 연산을 오류로 처리하지 않고(복귀) **단순히 무시**하여 병행성을 높입니다.
                    - 알고리즘
                        1. 트랜잭션은 항상 가장 최신 버전의 데이터를 판독
                        2. 트랜잭션이 너무 뒤늦게 기록하려고 하면 강제로 복귀
                        3. 트랜잭션이 어떤 버전의 데이터를 기록하려고 할 때 그 데이터
를 다른 트랜잭션이 판독해 버린 경우 → 기록 불허

> 17. 뷰 동등
> **1. 뷰 동등 (View Equivalence)**
> 두 스케줄 $S$와 $S'$이 데이터베이스 상에서 동일한 데이터 흐름과 최종 결과를 보장할 때 뷰 동등($S \equiv S'$)하다고 정의하며, 아래의 **3가지 조건**을 모두 충족해야 합니다.
>     - **동등한 초기 읽기 (Initial Read):** 스케줄 $S$에서 트랜잭션 $T_i$가 데이터 아이템 $x$의 초기값을 읽었다면, 스케줄 $S'$에서도 $T_i$가 $x$의 초기값을 읽어야 합니다.
>     - **동등한 의존성 읽기 (Dependent Read):** 스케줄 $S$에서 $T_i$가 읽은 $x$의 값이 $T_k$의 $write(x)$ 연산으로 생성된 값이라면, 스케줄 $S'$에서도 $T_i$는 $T_k$가 생성한 $x$의 값을 읽어야 합니다
>     - **동등한 마지막 쓰기 (Final Write):** 스케줄 $S$에서 $T_i$가 $x$에 대해 마지막으로 $write(x)$를 실행했다면, 스케줄 $S'$에서도 $T_i$가 마지막으로 $write(x)$를 실행해야 합니다.
>     - ==뷰 직렬 가능== 스케줄
> - 직렬 가능성 검사의 어려움
>     - 직렬 가능성 이론 이용
>         - 직렬 가능성 검사 수행하지 않음
>         - 로킹
>         - 타임스탬프
>     - 엄격한 2단계 로킹 규약
