## 세부 파일: 시험

#### **1. 그래프 기본 개념 및 인접 리스트 구현 (C언어)**

- **그래프(Graph)란?**
    - **정점(Vertex) +** **간선(Edge)**
    - **방향 그래프(Directed Graph)** vs **무방향 그래프(Undirected Graph)**
    - **가중치 그래프(Weighted Graph)**
- **그래프 표현 방식**
    - **인접 행렬(Adjacency Matrix)** 방식의 이해 및 장단점 파악
    - **인접 리스트(Adjacency List)** 방식의 이해 및 장단점 파악
- **C언어로 인접 리스트 구현하기**
    - **구조체(**`**struct**`**)**를 이용해 <u>정점(V)</u>과 <u>간선(E)</u> 표현하기
    - **동적 메모리 할당(**`**malloc**`**)**을 사용한 리스트 구현
    - 그래프 생성, 정점 및 간선 추가 기능 구현

#### **2. 그래프 기본 탐색 알고리즘**

- **깊이 우선 탐색 (DFS, Depth-First Search)**
    - **스택(Stack)** 또는 **재귀 함수(Recursive Function)**를 이용한 원리 이해
- **너비 우선 탐색 (BFS,    Breadth-First Search)**
    - **큐(Queue)**를 이용한 원리 이해
    - BFS가 최단 경로 탐색에 사용되는 이유 이해하기 (가중치가 없는 그래프의 경우)

---

#### **3. 최단 경로 탐색 알고리즘**

특정 정점에서 다른 정점까지 가는 가장 짧은 경로를 찾는 알고리즘들을 학습합니다. 각 알고리즘의 특징과 사용되는 상황이 다르므로 비교하며 공부하는 것이 중요해요.

- **다익스트라 알고리즘 (Dijkstra's Algorithm)**
    - <u>**하나의**</u>** 시작 정점**에서 **다른 모든 정점**까지의 최단 경로 탐색
    - *음수 가중치(Negative Weight)**가 없는 경우에만 사용 가능
    - **우선순위 큐(Priority Queue)**를 사용한 성능 개선 방법 이해 및 구현
- **플로이드-워셜 알고리즘 (Floyd-Warshall Algorithm)**
    - <u>**모든**</u>** 정점**에서 **다른 모든 정점**까지의 최단 경로 탐색
    - **동적 계획법(Dynamic Programming)** 기반의 원리 이해
    - 음수 가중치가 있어도 사용 가능 (단, 음수 사이클은 없어야 함)
    - 3중 반복문을 이용한 간단한 구현 이해

#### **4. 추가 그래프 관련 알고리즘 (심화)**

기본적인 탐색 및 최단 경로 알고리즘을 익힌 후, 그래프를 활용한 다른 문제들을 해결하는 알고리즘들을 학습합니다.

- **최소 신장 트리 (MST, Minimum Spanning Tree)**
    - 그래프의 모든 정점을 **최소 비용**으로 연결하는 방법
    - **크루스칼 알고리즘 (Kruskal's Algorithm)**: 간선 중심, **탐욕적(Greedy)** 접근
    - **프림 알고리즘 (Prim's Algorithm)**: 정점 중심, **탐욕적(Greedy)** 접근
- **위상 정렬 (Topological Sort)**
    - *순서(방향)**가 정해진 작업들을 처리하는 알고리즘
    - *방향 비순환 그래프(DAG, Directed Acyclic Graph)**에서만 적용 가능
    - DFS 또는 큐를 이용한 구현 방법 학습

#### **5. 고급 자료구조: 효율적인 데이터 관리**

#### **우선순위 큐 (Priority Queue)와 힙 (Heap)** heapq

'먼저 들어온 데이터'가 아닌 **'우선순위가 가장 높은 데이터'**가 먼저 나가는 자료구조입니다. 응급실 시스템을 생각하면 이해하기 쉬워요. 🚑

- **개념**:
    - 데이터를 넣을 때는 자유롭게 넣지만, 꺼낼 때는 우선순위가 가장 높은 것부터 나온다는 규칙을 가집니다.
    - 주로 **힙(Heap)**이라는 완전 이진 트리 기반의 자료구조로 구현됩니다.
- **힙 (Heap)의 종류**:
    - **최대 힙 (Max Heap)**: 부모 노드의 키 값이 자식 노드의 키 값보다 크거나 같은 완전 이진 트리입니다. **가장 큰 값**이 항상 루트에 위치합니다.
    - **최소 힙 (Min Heap)**: 부모 노드의 키 값이 자식 노드의 키 값보다 작거나 같은 완전 이진 트리입니다. **가장 작은 값**이 항상 루트에 위치합니다.
- **활용**:
    - **다익스트라 알고리즘**: 다음으로 탐색할 가장 가까운 정점을 찾는 데 최소 힙이 사용됩니다.
    - **운영체제 스케줄링**: 작업의 우선순위에 따라 프로세스를 처리할 때 사용됩니다.
    - 데이터 압축(허프만 코딩) 등

---

#### **해시 테이블 (Hash Table)**

키(Key)를 값(Value)에 직접 매핑하여 **매우 빠른 데이터 검색**을 가능하게 하는 자료구조입니다. 마치 사전에 있는 단어(Key)를 찾아 바로 뜻(Value)을 확인하는 것과 같아요. 📖

- **핵심 요소**:
    - **해시 함수 (Hash Function)**: 임의의 길이의 데이터를 고정된 길이의 데이터(해시값)로 매핑하는 함수. 좋은 해시 함수는 키를 해시 테이블 공간에 고르게 분배합니다.
    - **해시 충돌 (Hash Collision)**: 서로 다른 두 개의 키가 같은 해시값으로 매핑되는 현상.
- **충돌 해결 방법**:
    - **체이닝 (Chaining)**: 충돌이 발생하면 해당 해시값 위치에 연결 리스트(Linked List)를 만들어 데이터를 이어서 저장하는 방식.
    - **개방 주소법 (Open Addressing)**: 충돌 발생 시, 다른 비어있는 공간을 찾아 데이터를 저장하는 방식. (선형 탐사, 제곱 탐사 등)
- **장점**:
    - 데이터 삽입, 삭제, 검색의 **평균 시간 복잡도가 O(1)**로 매우 빠릅니다.
- **단점**:
    - 해시 충돌이 잦아지면 성능이 급격히 저하될 수 있습니다.
    - 순서가 있는 데이터(정렬된 리스트 등)를 다루기에는 적합하지 않습니다.

#### **6. 기본 정렬 알고리즘**

데이터를 특정 순서(오름차순, 내림차순 등)에 따라 재배열하는 것은 프로그래밍의 가장 기본적이면서도 중요한 작업 중 하나입니다. 각 정렬 방식의 원리와 장단점을 비교하며 이해하는 것이 중요해요.

- **버블 정렬 (Bubble Sort)**
    - **원리**: 서로 인접한 두 원소를 검사하여 정렬되지 않았으면 자리를 바꾸는 것을 반복합니다. 거품이 수면으로 올라오는 모양과 비슷하여 버블 정렬이라 불립니다.
    - **장점**: 구현이 매우 간단하고 직관적입니다.
    - **단점**: 시간 복잡도가 **O(n²)**으로 데이터가 많아지면 매우 비효율적입니다.
- **선택 정렬 (Selection Sort)**
    - **원리**: 전체 원소 중에서 가장 작은(또는 가장 큰) 원소를 찾아 첫 번째 자리의 원소와 교환합니다. 그다음 원소부터 이 과정을 반복합니다.
    - **장점**: 구현이 간단합니다. 데이터 이동 횟수가 버블 정렬보다 적습니다.
    - **단점**: 시간 복잡도가 **O(n²)**으로 비효율적인 것은 마찬가지입니다.
- **삽입 정렬 (Insertion Sort)**
    - **원리**: 두 번째 원소부터 시작하여 그 앞(왼쪽)의 이미 정렬된 데이터들과 비교하여 자신이 들어갈 위치를 찾아 삽입하는 방식입니다.
    - **장점**: 데이터가 거의 정렬되어 있는 경우 매우 효율적입니다.
    - **단점**: 평균 시간 복잡도는 **O(n²)**입니다.
- **안정 정렬 (Stable Sort) vs 불안정 정렬 (Unstable Sort)**
    - **안정 정렬**: 정렬 후에도 **값이 같은 원소들의 상대적인 순서가 유지**되는 정렬 방식입니다. (예: 버블 정렬, 삽입 정렬, 병합 정렬)
    - **불안정 정렬**: 정렬 후에 값이 같은 원소들의 상대적인 순서가 바뀔 수 있습니다. (예: 선택 정렬, 퀵 정렬, 힙 정렬)

| **알고리즘** | **장점** | **단점** | **시간 복잡도** | **안정 정렬** |
| --- | --- | --- | --- | --- |
| **버블 정렬** <br> (Bubble Sort) | - 구현이 매우 간단하고 직관적임<br>- 데이터가 이미 정렬된 경우 조기 종료 가능 | - 비교/교환 횟수가 많아 매우 비효율적임<br>- 데이터 양이 조금만 많아져도 속도가 급격히 느려짐 | **최선**: O(n)<br>**평균/최악**: O(n²) | **O** |
| **선택 정렬** <br> (Selection Sort) | - 구현이 간단함<br>- 데이터 교환 횟수가 적음 | - 데이터의 정렬 상태와 무관하게 항상 O(n²)의<br>  비교를 수행하여 비효율적임 | **최선/평균/최악**: O(n²) | **X** |
| **삽입 정렬** <br> (Insertion Sort) | - 데이터가 거의 정렬된 상태일 때 가장 빠름<br>- 안정 정렬이면서 제자리 정렬(In-place sort)임 | - 데이터가 많거나 역순에 가까울수록 성능이 급격히<br>  저하됨 | **최선**: O(n)<br>**평균/최악**: O(n²) | **O** |

#### **7. 고급 정렬 알고리즘**

기본 정렬 알고리즘의 O(n²) 성능을 개선한, 훨씬 효율적인 정렬 알고리즘들입니다. 실제 프로그래밍에서 표준 라이브러리의 정렬 함수는 대부분 이런 알고리즘들을 기반으로 구현됩니다.

- **병합 정렬 (Merge Sort)**
    - **원리**: **분할 정복 (Divide and Conquer)** 기법을 사용합니다. 리스트를 더 이상 나눌 수 없을 때까지 절반으로 나누고, 다시 정렬하면서 병합(Merge)합니다.
    - **장점**: 시간 복잡도가 항상 **O(n log n)**으로 안정적입니다. 안정 정렬입니다.
    - **단점**: 정렬 과정에서 추가적인 메모리 공간(임시 배열)이 필요합니다.
- **퀵 정렬 (Quick Sort)**
    - **장점**: 평균 시간 복잡도가 **O(n log n)**으로 매우 빠릅니다. 추가 메모리 공간이 거의 필요 없습니다.
    - **단점**: 최악의 경우(이미 정렬된 리스트 등) 시간 복잡도가 **O(n²)**이 될 수 있습니다. 불안정 정렬입니다.
- **힙 정렬 (Heap Sort)**
    - **원리**: **힙(Heap)** 자료구조를 이용하여 정렬합니다. 전체 데이터를 최대 힙으로 구성하고, 루트 노드(가장 큰 값)를 마지막 노드와 교환한 후 힙 크기를 줄여가며 반복합니다.
    - **원리**: **분할 정복** 기법 사용. 리스트 내에서 하나의 기준(pivot)을 정하고, 기준보다 작은 요소는 왼쪽, 큰 요소는 오른쪽으로 분할한 후 각 부분을 재귀적으로 정렬합니다.
    - **장점**: 시간 복잡도가 항상 **O(n log n)**입니다. 추가 메모리가 필요 없습니다.

| **알고리즘** | **장점** | **단점** | **시간 복잡도** | **안정 정렬** |
| --- | --- | --- | --- | --- |
| **병합 정렬** <br> (Merge Sort) | - 항상 **O(n log n)**의 성능을 보장함<br>- 안정 정렬이므로 데이터 순서 유지가 필요할 때 유용함 | - 정렬을 위한 추가적인 메모리 공간(원본 크기와 같은)<br>  이 필요함 | **최선/평균/최악**:<br>O(n log n) | **O** |
| **퀵 정렬** <br> (Quick Sort) | - 평균적으로 가장 빠른 성능을 보임<br>- 추가적인 메모리 공간을 거의 사용하지 않음 | - 피벗(pivot) 선택에 따라 최악의 경우 **O(n²)**의<br>  성능을 보일 수 있음 (예: 이미 정렬된 배열)<br>- 불안정 정렬임 | **최선/평균**: O(n log n)<br>**최악**: O(n²) | **X** |
| **힙 정렬** <br> (Heap Sort) | - 항상 **O(n log n)**의 성능을 보장함<br>- 추가적인 메모리 공간이 필요 없음 | - 데이터의 상태에 따라 퀵/병합 정렬보다 실제<br>  실행 시간은 조금 더 느릴 수 있음<br>- 불안정 정렬임 | **최선/평균/최악**:<br>O(n log n) | **X** |

- **단점**: 데이터의 상태에 따라 퀵 정렬이나 병합 정렬보다 실제 실행 시간은 느릴 수 있습니다.
